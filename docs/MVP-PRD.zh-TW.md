## 問題

POAP 平台停止服務後，舊 Token 仍在鏈上，歷史快照也可下載，但原本負責建立活動、發放、領取、管理與收藏展示的應用層消失。協會目前只有一位發行人，因此第一版不需要打造通用平台；需要的是一條自己可維護、能接續歷史 POAP 的最短發行管線。

若不處理，協會無法繼續發行新的數位紀念物，收藏者也只能在不同系統分開查看舊 POAP 與新內容。

## MVP 結論

第一版採用「先登記、後批次鑄造」：

1. 發行人用 JSON 提供圖片、文案、日期與數量。
2. 本機指令產生 D1 匯入檔與一次性領取連結。
3. 收藏者開啟領取頁，輸入 Base 相容的 `0x` 地址。
4. 系統原子性地消耗一次性領取碼，建立待鑄造紀錄。
5. 發行人從本機批次鑄造，不把發行私鑰放在網站。
6. 同一個地址頁合併顯示歷史 POAP 與協會的新紀念章。

這個方案刻意犧牲「即時鑄造」，換取較少的後端、較小的金鑰風險，以及更低的長期維護成本。

## 目標

- 發行人能在 15 分鐘內把一份活動 JSON 轉成可用的領取頁與一次性連結。
- 收藏者能在 2 分鐘內完成領取登記，成功率達 95% 以上。
- 同一地址頁能同時呈現歷史 POAP 與 2026 年 7 月後的新紀念章。
- Archive 與新發行資料完全分離；新功能不得改寫歷史快照。
- 正式環境不在 Worker 儲存發行私鑰，MVP 也不依賴 POAP.in 的 API 或資料庫。

## 非目標

- 不做多發行人帳號、角色、審核與權限系統。
- 不做視覺化發行後台；單一發行人先使用 JSON 與命令列。
- 不做即時代付 Gas；先由發行人從本機批次鑄造。
- 不做完整 Email 行銷或寄信服務；現有 Email 流程只需放入唯一領取網址。
- 不做全鏈即時 POAP indexer；歷史層仍明確標示為固定快照。
- 不以 Collections、Moments、個人網站匯出阻擋 MVP 上線。

## 使用者故事

### 發行人

- 身為唯一發行人，我想用一份設定檔建立活動，以便不必維護複雜後台。
- 身為發行人，我想產生指定數量的一次性網址，以便放進 Email 或 QR Code。
- 身為發行人，我想匯出所有已登記地址，以便從自己的安全環境批次鑄造。
- 身為維護者，我想讓歷史資料維持唯讀，以免新功能破壞 Archive 的可信度。

### 收藏者

- 身為參與者，我想從 Email 或 QR Code 開啟領取頁，以便了解我正在領取什麼。
- 身為參與者，我想輸入既有錢包地址完成登記，不需要在網站支付 Gas。
- 身為收藏者，我想在同一個地址頁看到舊 POAP 與新紀念章，不需要理解兩套後端。
- 身為收藏者，我想知道紀念章目前是「待鑄造」或「已鑄造」，避免網站誤導我。

## P0 必須完成

### 歷史資料

- 匯入官方 `poap.sqlite` 的 Drops 與 Holdings。
- 保存圖片到自有 R2，前端不依賴 `media.poap.in`。
- 地址頁可讀取固定快照，並清楚呈現快照時間。

驗收：

- 給定一個快照中存在的地址，打開地址頁時可看到其歷史 POAP。
- 停用 POAP.in 網路存取後，正式站的歷史圖片與資料仍可使用。

### 活動建立

- 發行人可用 JSON 定義活動。
- 指令產生 D1 SQL 與一次性領取網址 CSV。
- D1 只保存領取碼的 SHA-256，不保存原始碼。

驗收：

- 給定有效活動 JSON，指令會產生 `load-event.sql`、`claim-links.csv` 與摘要。
- `claimCount` 不可超過 `maxSupply`。
- 同一領取碼無法成功使用兩次。

### 公開領取頁

- 顯示圖片、標題、說明、活動日期、供應量與已登記數。
- 接受完整 `0x` 地址。
- 缺少、過期、已使用或錯誤的領取碼會顯示明確錯誤。

驗收：

- 有效碼與地址會建立一筆 `reserved` 紀錄。
- 重送同一碼回傳衝突，不覆寫原地址。
- 無效地址不會寫入資料庫。

### 新舊收藏合併

- 地址頁同時查詢 Archive Holdings 與 Live Holdings。
- 新紀念章顯示 `reserved` 或 `minted` 狀態。
- 其中一個資料源暫時失敗時，另一個仍可顯示。

驗收：

- 完成登記後開啟該地址頁，可在歷史 POAP 之前看到新紀念章。
- Live DB 失敗時，歷史收藏仍可瀏覽。

## P1 下一階段

- 一次部署一份自有 ERC-1155 合約至 Base。
- 一個活動對應一個 token ID。
- 本機批次鑄造工具：讀取待鑄造地址、送出交易、回寫交易雜湊。
- 圖片與 metadata 上傳 R2 或內容定址儲存。
- 領取完成與鑄造完成 Email。
- 協會品牌、網域、隱私政策與移除／更正聯絡方式。

## P2 未來

- 多發行人與網頁後台。
- 即時 Gas 代付、Paymaster 或受控 Relayer。
- WalletConnect／內嵌錢包，取代手動貼地址。
- 活動報表、重寄 Email、客服工具與撤銷流程。
- 對其他組織開放發行。

## 成功指標

領先指標：

- 首場測試活動產生 10 個連結，至少 8 個成功登記。
- 有效連結登記成功率 ≥ 95%。
- 領取中位時間 ≤ 2 分鐘。
- 重複領取造成的重複資料為 0。

落後指標：

- 30 天內不需外部工程師處理日常發行。
- 每場活動人工處理時間 ≤ 30 分鐘，不含內容製作。
- 月固定雲端費用維持在 NT$1,000 內，不含鏈上費用與網域。

## 尚待確認

非阻擋：

- 品牌正式名稱是「兆量富足教育協會」或先前提到的「朝陽富足教育協會」。
- 第一個正式活動的名稱、圖片、日期、供應量與領取截止日。
- 歷史資料要部署完整快照，或只公開協會已核對的 Drop allowlist。

進入鏈上階段前必須確認：

- ERC-1155 合約的名稱、symbol、管理地址與升級政策。
- 批次鑄造使用一般管理錢包、多簽或硬體錢包。
- 收藏者是手動貼地址，或第一版就加入錢包連接。
- 何時把 `reserved` 視為收藏的一部分，何時只顯示已確認上鏈項目。

完整階段、相依關係與驗收閘門見 [Phase 0–6 Roadmap](ROADMAP.zh-TW.md)。

- Phase 3：Base 主網與新收藏查詢。
